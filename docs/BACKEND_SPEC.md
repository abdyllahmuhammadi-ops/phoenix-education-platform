# مشخصات بک‌اند لازم برای ققنوس

هدف: جایگزین `window.storage` و `localStorage` و واسط امن برای هوش مصنوعی. فناوری پیشنهادی: Node.js + Express + PostgreSQL (یا SQLite برای شروع کوچک)، پشت Nginx با HTTPS.

## الف) ذخیره‌سازی کلید-مقدار (جایگزین window.storage)
رابط مورد انتظار سامانه: `get(key, shared)`، `set(key, value, shared)`، `delete(key, shared)`، `list(prefix, shared)`.
- `shared=true`: داده مشترک (مثل فهرست مدرسه‌ها)؛ `shared=false`: مخصوص کاربر.
- نقطه‌های پیشنهادی: `GET/PUT/DELETE /api/kv/:key?shared=0|1` و `GET /api/kv?prefix=…`.
- مقدار: متن JSON تا حدود ۵ مگابایت. هر نوشتن باید اتمی باشد.
- راه کم‌هزینه: به‌جای بازنویسی همه کد، یک لایه کوچک `window.storage` در مرورگر که به این API وصل شود (توابع `authStorageGet/Set` بدون تغییر می‌مانند).

## ب) احراز هویت و دسترسی (حیاتی)
سامانه فعلی همه چیز را در مرورگر می‌چیند و فقط به درستی رفتار مرورگر اعتماد دارد. در سرور **حتماً** باید:
- ورود با شناسه + رمز (رمزها با bcrypt/argon2)، نشست با توکن کوتاه‌عمر.
- قاعده دسترسی برای هر پیشوند کلید: مثلاً فقط مدیر سامانه به `free-access` و `system-suggestions`؛ دانش‌آموز فقط داده خود؛ معلم داده کلاس‌های خودش.
- محدودیت نرخ و ثبت لاگ حسابرسی.
- **هرگز** دانش‌آموز با دانش‌آموز پیام مستقیم نداشته باشد (قانون ثابت).

## ج) واسط هوش مصنوعی
- `POST /api/ai` با بدنه همان ساختار `messages` فعلی؛ سرور کلید API را از متغیر محیطی می‌خواند و درخواست را به سرویس هوش مصنوعی می‌فرستد.
- کلید هرگز در مرورگر یا مخزن نباشد. سقف تعداد درخواست برای هر کاربر، و کش پاسخ‌ها.
- چون سرور ایران ممکن است دسترسی مستقیم نداشته باشد، این واسط روی سروری در خارج از ایران اجرا شود و سامانه فقط به آن وصل شود.
- در سامانه ۱۵ نقطه باید آدرس را از `https://api.anthropic.com/v1/messages` به آدرس واسط تغییر دهند.

## د) فایل‌های ثابت
تصویر و ویدئو روی میزبانی جدا یا CDN؛ React، Babel (یا بهتر: کد پیش‌کامپایل‌شده) و فونت روی خود سرور.

## ه) پشتیبان‌گیری
پشتیبان روزانه پایگاه‌داده + هفتگی کل سرور، با آزمون بازیابی دوره‌ای.
